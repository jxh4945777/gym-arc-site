为什么选 Gym-Arc

别人告诉你有没有违规，我们告诉你每一步值多少

同一条规则，在不同决策点上的代价不同。Gym-Arc 把这套后果结构算出来，这正是训练「会读规则的模型」所需要的。

每一步都有价格

在每个决策点，对每个合法动作做反事实推演，得到期望价值和 regret。模型学到的是权衡，而不只是对错。

不偷看答案

标签只用模型能观测到的信息。换成这种标签后，银保销售场景的决策损失减少一半以上。

合规是底线

任一约束不过，整局 0 分。业务结果单独报告、不进奖励，违规永远不划算。

加企业，不加代码

企业之间只差一份规则文件。新增一家零代码，从规则到环境可用不到一秒。

新行业，声明即可

在一个 YAML 里描述客户、动作、规则和奖励，模拟器、gold、Verifier 和实验由框架提供。三个新行业都是 0 行领域代码。

经得起审计的结果

实验设计在训练前提交，有 git 时间戳为证；文档和控制台里的每个数字都由自动化守卫复核。

FAQ

客户常问的问题

需要提供真实客户数据吗？

不需要从客户数据开始。环境由你的规则手册和表格构建；如果有历史工单，会用来校准那些只体现在结果里的规则，比如审批时效、核保尺度。

数据和产出归谁？

合同里写清五项：源数据归属、通用框架、任务与评测方法、由你的规则派生的合成资产，以及能否授权给其他客户。从第一天起就写进协议。

支持哪些模型？

任何能通过 Gymnasium 或 Hugging Face TRL 训练的模型，以及自研的结构化决策模型。通用大模型可以作为 baseline 或 Judge 接入。

为什么不直接把规则手册给大模型？

读了手册的大模型，仍然判断不了这条规则在当前这一步值多少。在我们的对比中，环境里训练出的决策模型比拿到规则的通用大模型准确率高 17.9 个点，速度快 112 倍。

能部署在我们自己的服务器上吗？

可以。环境、接入和训练都是 Python，跑在你的 GPU 服务器上；控制台是静态页面，离线也能用。

接入一家企业要多久？

平台侧不用改代码，规则到环境可用不到一秒。整体周期主要取决于资料准备；我们提供手册骨架、表格模板和接入问卷，帮你一次做对。
